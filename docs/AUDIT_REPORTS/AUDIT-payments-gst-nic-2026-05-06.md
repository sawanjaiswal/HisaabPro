## Ship-gate assessment

**BLOCKED.** Six P0 issues — most importantly (A) every Collections frontend call is double-prefixed `/api/api/...` and 404s, (B) the Razorpay webhook writes the dedupe row outside the payment transaction (lose-payment risk on tx rollback), (C) the aging SQL filters on the wrong document `type` literal (`SALES_INVOICE` vs canonical `SALE_INVOICE`) so the dashboard returns zero rows, and (D) the PTP create/update contract names diverge between client (`promisedDate`/`note`) and server (`promiseDate`/`notes`) so every PTP write 400s. None of these would have surfaced in static checks but all are reproducible in 30 seconds of manual testing. Fix the P0s, then re-run; the P1 list is small enough to land in the same change.
