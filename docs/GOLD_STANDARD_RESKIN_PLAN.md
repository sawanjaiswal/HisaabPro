## 1. The one delta that dominates every remaining page

Grepping all 29 target pages for the design-language primitives returns:

- **`HeroPage` usage: 0 / 29**
- **`SummaryTiles` usage: 0 / 29**

Every reskinned page in Waves 1–4 mounts `<HeroPage>` (emerald band + white
rounded sheet) and, where it has stats, `<SummaryTiles>`. None of the remaining
pages do. **That single swap is ~70% of the visual delta on nearly every page**,
and it is a mount, not a redesign — `HeroPage` recolours `<Header>` for free.

The other four recurring deltas, in frequency order:

2. **Tinted icon-square rows** — settings/list rows currently render as plain
   rows with an untinted icon. Mockups #74, #97, #98, #19, #25 are all the same
   grouped-list motif (archetype **H**).
3. **Segmented chip filter row** (archetype **C**) — mockups #71, #63, #45, #49
   show `All (12) / Active (9) / Inactive (3)` pills; current pages use plain
   `<Tabs>` or nothing.
4. **Sticky bottom CTA** via `<BottomActionBar>` — mockups #58, #78, #79, #85,
   #92 end in a full-width emerald CTA; several current pages inline the button
   mid-page.
5. **Status pills** → `<Badge variant>` — a handful of pages still hand-roll
   coloured spans.

**Consequence for sequencing:** there is no new primitive to build first. Wave 10
is closed (`GPT_REDESIGN_PLAN.md` §5) and every motif above already exists in
`src/components/ui/`. This sweep is **mount-and-restyle, not build**.

## 4. Per-page execution contract (no exceptions)

Each page is one `/hp-design` cycle and **one commit**:

1. **Phase 0.5 inventory** — grep for the capability before adding anything.
   `HeroPage`, `SummaryTiles`, `TransactionRow`, `Badge`, `FilterChips`,
   `ResponsiveTable`, `BottomActionBar`, `PeriodGroup`, `ListTotalsFooter`,
   `Accordion`, `DropdownMenu` all already exist. **Reuse is the default; a new
   component needs the Phase-0.75 written justification.**
2. **Phase 1 component map** — every mockup element → an existing component.
   More than 2 `NONE` rows on a single page = stop and re-scope.
3. **Phase 2 plan** → `.claude/design-plan-active.md`, `status: approved` before
   any write (the gate enforces this).
4. **Phase 3 build** — `HeroPage` mount first, then rows, then states. 6-layer
   split if the page crosses 250L.
5. **Phase 4 verify** — all three must print their token:
   ```
   npx tsc -b --noEmit                            && echo TSC_OK
   node scripts/enforce.js                        && echo ENFORCE_OK
   node .claude/skills/hp-design/check-refs.mjs   && echo REFS_OK
   ```
   plus screenshots of all 4 states at 320 / 375 / 768, light **and** dark.

**Non-negotiables per page** (these are the ones reviews actually catch):

- Two-greens: brand emerald = CTA/nav/underline/FAB; success green = status only.
- Every section container `py-0`; section groups stack `space-y-6`.
- Amounts: paise on the wire, `formatCurrency()` + `tabular-nums` on screen.
- All strings `t.*` in **both** `translations.en.ts` and `translations.hi.ts`.
- Offline: `api()` only, mutations carry `entityType` + `entityLabel`.
- Tap targets ≥44px; bottom-nav clearance via `--bottom-nav-height`.

## 6. Known risks

| Risk | Mitigation |
|---|---|
| Reskin silently breaks a data contract (4th instance of the hand-written-DTO bug class — see `.claude/fix-trace-pos-contract.md`) | Any page whose reskin touches data shape gets its types re-derived from the server contract, not hand-written |
| `HeroPage` mount changes header geometry on pages with custom sticky strips | Offset against `var(--header-height)`, never `top: 0` (PLATFORM_SHELL C10) |
| Settings wave's 18 near-identical screens invite copy-paste divergence | W8a lands the row motif once; W8b/8c reference it rather than re-deciding |
| A page crosses 250L mid-build | Plan the 6-layer split in Phase 2, before writing — splitting after costs a `/garden` cycle |
